# پچ ۶۰-و — فیکس بحرانی: تیکِ داشبورد کل پنل را باز نمی‌کند

> تاریخ: 2026-11-22 · علتِ نهاییِ همهٔ گزارش‌های «منو برای صندوق‌دار باز است»:
> در تطبیق مسیرها، تیکِ «داشبورد» (مسیر `/admin`) با چکِ پیشوندی
> `startsWith('/admin/')` روی **هر صفحهٔ `/admin/*`** هم true می‌داد —
> یعنی همان یک تیک، عملاً تمام ماژول‌ها را برای همه باز می‌کرد.

## تغییر

| فایل | تغییر |
| --- | --- |
| `lib/admin/modules.ts` | `accessAllowsPath`: مسیر `/admin` در تطبیق پیشوندی نادیده گرفته می‌شود (فقط exactِ داشبورد را باز می‌کند) — پروکسی و گاردهای API/سرور همه از همین تابع استفاده می‌کنند |
| `app/admin/layout.tsx` | `menuAllows`: همین فیکس در فیلتر منوی سایدبار |
| `lib/version.ts` | مُهر نسخه → `60f` |

رفتار درست پس از فیکس، برای لیست `[dashboard, orders, orders/new]`:
- داشبورد ✓ · سفارش‌ها ✓ · ثبت سفارش حضوری ✓
- حسابداری/مشتریان/کاربران/دسترسی ماژول‌ها/کاتالوگ/… ✗ (منو مخفی + URL مستقیم → داشبورد + API → ۴۰۳)

## نصب

`patch-60f-prefix-fix.zip` را روی ریشهٔ پروژه Extract کن (Replace → بله؛
VS Code و `npm run dev` بسته باشند):

```powershell
git add -A
git commit -m "60f: critical fix — dashboard tick no longer opens whole /admin tree"
git push origin main
```

## راستی‌آزمایی

1. Vercel → Deployments → آخرین Production Ready شود.
2. پنجرهٔ ناشناس: `/api/admin/whoami` → باید `"build":"60f"` ببینی.
3. پنل با **Ctrl+Shift+R** → منوی c2 فقط: داشبورد، سفارش‌ها، ثبت سفارش حضوری.
4. `/admin/accounting` دستی → برگشت به داشبورد؛ `/admin/access` دستی → برگشت به داشبورد.
5. با اکانت مالک: همهٔ منوها همچنان باز + صفحهٔ 🧩 سالم (تیک‌زدن/ذخیره دوباره تست شود).
